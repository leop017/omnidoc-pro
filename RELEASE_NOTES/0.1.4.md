# v0.1.4 — 真实 Bug 修复 + Excel 合并单元格与分块策略改进

**OmniDoc Pro** v0.1.4 是 v0.1.3 的功能修复版本，解决了三个已验证的确定性 Bug：Markdown 分片策略静默失效、多工作表 Excel 全部失败时状态误报为 OK、以及 Excel 导出路径中合并单元格 rowspan 属性丢失。

## 🐛 Bug 修复

### Markdown 分片策略静默失效（BUG-A，高影响）

**现象**：用户在 WebUI / CLI 选择 `--chunk-strategy markdown` 后，输出的 chunks 恒为空列表（0 个），且**无任何警告或错误**，下游 RAG 管线静默损坏。

**根因**：所有引擎只填充 `Document(text=...)`，从不填充 `Document.elements`；而 `MarkdownChunker` 第一行检查 `if not doc.elements: return []`，导致该策略在现有架构下永远返回空。

**修复**：`MarkdownChunker` 新增 `_heading_elements_from_text()` 回退路径——当 `doc.elements` 为空时，解析 `doc.text` 中的 heading（`#`、`##` 等）和段落结构，生成等价于 `elements` 的分组。该策略现在与普通策略同样可用，并可在正常产出零 chunk 时记一条 warning 提示用户。

**影响**：`strategy="markdown"` 恢复正常工作，WebUI 的 Radio 选项不再虚设。

### 多工作表 Excel 全部失败时 status 误报为 OK（BUG-B，中影响）

**现象**：当多工作表 Excel 文件的所有 sheet 均解析失败时（如损坏文件），`_result_multi()` 返回 `status=OK`、`success=False`、非空 `errors` 列表，状态字段自相矛盾。经 controller 路径时可被 fallback 兜底，但直接调用 `DeepEngine.convert_document()` 的调用方会拿到误导性的 OK 状态。

**修复**：全表失败分支补设 `status = ConversionStatus.ERROR`，与异常分支处理保持一致。

### Excel HTML 导出表头 colspan 漏发 rowspan

**现象**：`.xlsx` 文件的 `<table>` 输出中，master 表头单元格若同时拥有 `colspan > 1` 和 `rowspan > 1`，只输出 `colspan` 属性，`rowspan` 属性丢失，导致 HTML 表格渲染错位。

**修复**：`_build_html_table` master 分支在 `colspan>1` 之外，同时判断 `rowspan>1` 并追加对应属性。

## 🔧 其他修复

- **`clean_filename` 字符级截断**：原来按字节数截断 UTF-8 字符串，对含 CJK 字符的文件名会产生 `\ufffd` 替换字符。改为按字符数截断（保留前 180 个字符）。
- **`llm_service` 错误消息脱敏**：`test_llm_connection` 失败时，错误信息中的 API key 会被替换为 `****`，避免意外泄漏。
- **`deep_engine` 异常分支状态统一**：解析异常时设置 `status=ConversionStatus.ERROR` 并写入 `errors`，不再静默保留默认 OK 状态。

## 🧪 测试覆盖

- `tests/test_excel_builder.py`：新增 `TestMergedHeaderRowspan`（3 用例：HTML colspan+rowspan、enhanced_md 子表头保留、`_remap_merged_rows` 恒等映射）。
- `tests/test_chunkers.py`：新增 `test_markdown_fallback_to_headings`、`test_markdown_warning_on_zero_chunks`，锁定回退行为与 warning 机制。
- `tests/test_deep_utils.py`：更新 `test_long_cjk_name_char_truncated`，断言 200 个 CJK 字符截断后为 180 个字符、无 `\ufffd`。
- `tests/test_smoke_integration.py`：新增 `TestDeepAllSheetsFail`，验证多工作表全失败时 `status=ERROR`。
