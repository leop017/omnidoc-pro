# v0.2.1 — 深度代码评估修复：安全加固 + 数据一致性 + 工程质量

**OmniDoc Pro** v0.2.1 是一次全面的质量修复版本。基于对全部代码的深度评估，修复了 3 个高严重度问题（SSRF 绕过、LLM 图像描述链路断裂、文件名碰撞），以及一批中低严重度问题（降级链失效、清洗越界、CLI 校验缺失等）。全部 351 个测试通过，mypy 从 27 个错误降至 0 个。

## 🛡️ 安全加固（H1）

### SSRF 防护绕过修复

`MarkItDownEngine` 的 URL 抓取原先仅校验解析后的 `ip` 是否为私网地址，但实际请求仍通过 `requests`/urllib 跟随重定向并二次解析 DNS——攻击者可让首个 IP 为公网、后续跳向 `127.0.0.1` 或内网（DNS rebinding / 重定向绕过）。

**修复**：

- **IP 钉扎 + SNI 保留**（`_fetch_via_ip`）：用 `urllib3.HTTPSConnectionPool(ip, port, server_hostname=parsed.hostname)` 建立连接，确保实际连到验证过的 IP，同时 TLS 握手仍使用原始 hostname（SNI 正确）。
- **手动重定向循环**（`_fetch_safe_html`）：每次 3xx 都重新解析新 Location 的 IP 并校验，超过 `_MAX_REDIRECTS=10` 次抛 `ValueError`。
- **扩展私网判定**（`_EXTRA_PRIVATE_NETS`）：CGNAT（`100.64.0.0/10`，Tailscale 等）与 NAT64（`64:ff9b::/96`）现在也被拦截。
- **超时**（M8）：`openai.OpenAI` 构造新增 `timeout=float(llm.get("timeout", 30.0))`。

> 此版本还修复了一个 `urllib3 2.7` 运行时 bug：`HTTPConnectionPool` 无 `clear()` 方法（已改用 `close()`）。

## 🔧 数据一致性修复

### LLM 图像描述链路 100% 断裂（H2）

`_describeable_image_refs` 原先返回 `m.group(0)`（含 `![` 前缀的完整引用），导致即使 mammoth 生成 `data:` URI，`startswith("data:")` 检查也永远失败——**所有图像形式 100% 无法被 LLM 描述**。

**修复**：

- `_describeable_image_refs` 改为返回 `(full_ref, bare_url)` 元组对，从 `![alt](url)` 中提取裸 URL。
- `_to_data_uri(url)` 参数改名，仅接受裸 URL。
- `_run_bounded` 返回 `(descs, failures)`，逐图收集失败原因。
- `enhance` 将 failures 汇总进 `DocumentResult.warnings`（全部失败 / 部分失败，附前 3 条原因）。

### 文件名碰撞（H3）

同 stem 源（`a/report.docx` + `b/report.docx`）会产生同名下载文件，静默丢失首个结果。

**修复**：

- 新增 `safe_download_stem()` 共享 helper（`document.py`），`safe_download_name()` 复用之。
- WebUI `_unique_download_name(source, ext, used)` 与 CLI `_unique_cli_name(stem, ext, used)` 使用批次共享 `set`，数字后缀落在源 stem 上（`report_1.chunks.jsonl` 而非 `report.chunks_1.jsonl`）。
- 引擎层 `deep_engine._claim_name` 同步去重。

### 降级链失效 + UI 开关虚假（M1）

`breadth` 引擎的 `supports()` 排除全部深度格式，导致 fallback 链恒为 `[deep]`，"Deep → MarkItDown" 文档承诺的降级从未发生；UI 上的引擎切换对深度格式形同虚设。

**修复**：

- `supports()` 改为 `ext not in _UNPARSEABLE_EXTS`（仅 `.doc` 排除），让 `.docx`/`.xls`/`.xlsx` 可被 breadth 引擎认领作为真实 fallback。
- 控制器判定从 `if result.markdown:` 改为 `if result.status == ConversionStatus.OK:`（M1），避免空 markdown 被误判为成功。
- 空 markdown / 原始文件回显（MarkItDown 0.1.x plaintext fallback 对损坏二进制返回原始字节）现在都判为 `ERROR` + 明确错误信息。

## 🧹 工程质量

- **M2 CLI 分块参数校验**：`cmd_convert` 入口调用 `cfg.chunking.validate_issues()`，非法参数 `exit 2`（与 WebUI 行为一致）。
- **M3 CLI 导出选项**：新增 `--output-dir` 与 `--export-chunks`，输出路径与 WebUI 对齐。
- **M4 .doc 可用性提示**：`deep_engine` 检测 `textract` 缺失时给出明确 `ValueError` 信息，而非模糊的 ImportError。
- **M5 清洗越界 + 写盘顺序**：`_TABLE_FORMATS` 对表格源 scope-out `remove_duplicate_headers`；`_sync_written_files` 在管线运行后重写引擎 `.md` 文件为清洗后 markdown。
- **M7 临时目录清理**：`_cleanup_stale_tempdirs(max_age_hours=24)` 在 `main()` 入口清理 24h 前遗留的 `omnidoc_webui_*` 目录。
- **L2 / L6 / L8 低优先级修复**：`_enhance` 返回 `DocumentResult`；`word_md.py` falsy 规则修正；`test_llm_connection` 空内容防御。
- **mypy**：`Optional` 标注、`_excel.py` 返回类型、`cli.py` `reconfigure` 忽略、`config.py` `validate` 改名 `validate_issues` 避开 Pydantic 内置方法。
