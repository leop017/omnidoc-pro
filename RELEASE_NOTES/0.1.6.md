# v0.1.6 — 打通 `max_chunk_size` 契约

**OmniDoc Pro** v0.1.6 是 v0.1.5 的功能增强版本，修复了一处配置契约断裂：`max_chunk_size` 字段此前只在 `MarkdownChunker` 内部消费，`ChunkingSettings` 未声明该字段，导致 CLI 与 WebUI 产品入口**永远无法触达**该功能。

## ✨ 功能增强

### `max_chunk_size` 端到端打通

**现象**：`MarkdownChunker` 的 `max_chunk_size` 参数（控制单 markdown 子树的切分上限）只能通过手写 `DocumentResult` 时手工注入 `config` 字典才生效；从 CLI `omnidoc convert` 或 WebUI 提交任务时，`ChunkingSettings` 的 Pydantic 模型没有该字段，`to_engine_kwargs()` 不会导出它，`pipeline._chunk` 也不会转发，用户**实际无法启用**该功能。

**修复**（4 个文件）：

| 文件 | 变更 |
|------|------|
| `omnidoc/core/config.py` | `ChunkingSettings` 新增 `max_chunk_size: int = 0` 字段（0 = 不切分） |
| `omnidoc/ui/cli.py` | 新增 `--chunk-max-size` CLI 选项，经 `_build_config` 透传到 `cfg.chunking.max_chunk_size` |
| `omnidoc/ui/webui.py` | 新增 `chunk_max_size` 数字控件，纳入 `_on_convert` → `_build_config` → 全链路 |
| `tests/test_contracts.py` | 新增 `test_chunking_settings_carries_max_chunk_size` 锁定契约 |

**影响**：markdown 策略下用户可通过 CLI `--chunk-max-size` 或 WebUI 控件控制单个标题子树的最大字符数，超长子树会被进一步切分，RAG 入库粒度的可控性提升。

## 🧪 测试覆盖

## 已知限制

- exe 仍为 Windows 构建（CLI / WebUI）；Linux/macOS 请通过 `pip install` 安装 Python 版本。
- LLM 增强功能需自行配置 API key（OpenAI / Ollama / 兼容 API）。
- `max_chunk_size` 仅对 markdown 策略生效；fixed / sentence 策略不受该字段影响。
