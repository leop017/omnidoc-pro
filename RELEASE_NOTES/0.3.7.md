# v0.3.7 — 零风险修复： CleaningSettings.enabled 实现 + WebUI LLM provider 透传

**OmniDoc Pro** v0.3.7 包含 2 项零风险缺陷修复。全套测试 **404 passed** 保持不变。

## 🔧 修复清单（2 项）

### 1. 🧼 `OmniDocConfig.cleaning.enabled` 全链路未消费 bug 修复

**问题**：
- `CleaningSettings.enabled` 字段定义在 [core/config.py](omnidoc/core/config.py) 中，但 `OmniDocConfig.to_engine_kwargs()` 只导出 `cleaning_rules` 4 个规则（`remove_empty_lines`, `normalize_spaces`, `strip_page_numbers`, `dedup_repeats`），不导出 `enabled`。
- `_clean`（[processors/pipeline.py](omnidoc/processors/pipeline.py)）只看 `cleaning_rules` 是否有 True 值，从不检查 `enabled`。
- Deep Engine（`_sheet_to_md`）同样基于 `config["cleaning_rules"]` 判定，与 enabled 不同步。
- 结果：用户设 `cleaning.enabled=False`（但 rules 4 个默认全 True）时，清洗仍执行，语义失效。

**修复**：
- `to_engine_kwargs()` 增加 `"cleaning_enabled": self.cleaning.enabled`
- `_clean` 入口：`if not config.get("cleaning_enabled", True): return`
- Deep Engine `_sheet_to_md`：`if not config.get("cleaning_enabled", True): rules = {}`
- 默认 `True`，旧行为 100% 兼容。

**风险 = 0 的论证**：
- 仅落实已有配置语义（`enabled` 字段原以 fields str 未使用），无行为变化；
- 默认值 `True` 保证旧行为；
- 所有现有测试（404 passed）不变——当前测试均只设 `cleaning_rules`，不设 `enabled`。

### 2. 🌐 WebUI LLM 探测缺 provider 透传（v0.2.9 已知遗）

**问题**：
- `_on_test_llm` 签名 `(base_url, api_key, model)`，不接受 `provider`；传入 `test_llm_connection` 的 dict 无 `provider` 键；
- `test_llm_connection` 无 provider 时走 raw-dict 默认路径，`_api_key_ok` 严格要求 key 非空；
- 直接后果：Ollama 用户在 WebUI 点"测试连接"、空 API Key 提交 → 报"请先填写 API Key"，功能被阻断；而 CLI `cmd_test_llm` 通过 `--llm-provider` 明确支持 Ollama 无 key 探测——不对称。
- release notes 0.2.9 已明确："omnidoc/ui/ 全 repo 零处出现 provider"，这是遗留项。

**修复**：
- `_on_test_llm` 增加 `provider` 参数，转发到 `dict["provider"]`（含 env `OMNIDOC_LLM_PROVIDER` 回退）
- `build_app`：
  - 新增 `llm_provider = gr.Radio(["openai","ollama"], value="openai", label="Provider")`
  - `test_btn.click` inputs 增加 llm_provider
  - `_convert` 入参链与 `_build_config` 入参链追加 `llm_provider`
  - `_build_config` 增加 `llm_provider` 并写入 `cfg.llm.provider`
  - `_on_convert` 也追加 `llm_provider`，与 WebUI conv btn input list 一致
- 默认 openai 时完全兼容原行为。

**风险 = 0 的论证**：
- 纯参数透传，不新增逻辑分支；
- provider 默认值 `aopenai` 等同原 dict 无 provider 时的默认 `openai` 行为；
- 全量 404 tests 通过（包括 test_webui 54 个）。
