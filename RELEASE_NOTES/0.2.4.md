# v0.2.4 — 可跳过 sheet 不误报 DEGRADED + 分块元数据嵌套 list 隔离 + 写盘韧性 + CLI 输出净化

**OmniDoc Pro** v0.2.4 是针对「子代理审计偏误」的三轮修复。基于对子代理报告的逐条源码复核与决定性探针验证，从 15 条疑似问题中筛出 4 条真实缺陷并全部修复，其余 11 条经探针证实为误报（子代理只报"可疑点"不报"安全点"，故须人工过滤）。全部 372 个测试通过，ruff 全部通过。

## 🔵 高严重度：空 / 不存在的 sheet 被误报 DEGRADED（H1-deep）

### 问题

`_excel.py` 的 `build()` 把"调用方指定的 sheet 在工作簿里不存在（工作表不存在）"和"sheet 数据为空（`_prepare` 抛 `ValueError("工作表为空")`）"两种**可跳过**的状态塞进了 `errors`。`_result_multi` 只要 `errors` 非空就标 `DEGRADED`，导致一个完全正常、只是含一个空 sheet 的 `.xlsx` 在 CLI 里被报告为 `exit 1`（v0.2.2 引入的回归）。

**探针验证**：构造含 "Full" + "Empty" 两 sheet 的 `.xlsx`，旧实现 `result["errors"]==[("Empty","工作表为空")]`，下游 `_result_multi` 判 `DEGRADED`；修复后 `errors==[]`、`skipped==[("Empty",...)]`，状态回 `OK`。

### 修复

`build()` 新增 `skipped` 返回值与 `metadata["skipped"]` 顶层键，区分三类：

- **`skipped`（可跳过，无内容损失）**：① 调用方点名但工作簿缺失的 sheet（`load_sheets` 静默过滤，故在 `build` 内层循环前用 `requested` 与 `all_sheets` 求差集补种）；② 空 sheet（`_prepare` 的 `ValueError`，被新加的 `except ValueError` 捕获）。
- **`errors`（真失败）**：不支持的输出格式等。`_sheet_content` 对非法格式的 `ValueError` 现**在 try 外**预先校验并逐 sheet 记 `errors`，不被 `except ValueError` 误降级（保住既有契约）。
- 单 sheet 早退路径与空工作簿路径也补齐 `"skipped": []`。

`_result_multi` 消费 `skipped`/`errors`：`skipped` 只 `add_warning`（结果保持 `OK`），仅当 `errors` 非空才标 `DEGRADED`。

## 🧩 高严重度：make_chunk 嵌套 list 浅拷贝泄漏（make_chunk）

### 问题

`base.py` 的 `make_chunk` 用 `dict(metadata)` 只复制**顶层**映射。Deep Engine 多 sheet 路径把 per-sheet 摘要 list 嵌在 `metadata["sheets"]`，于是每个 Chunk 与源 `Document.metadata`、以及彼此之间**共享同一个 list 对象**。下游对某个 chunk 原地 `append` 会串改兄弟 chunk 并回写到源 Document。

**探针验证**：`c1.metadata["sheets"] is c2.metadata["sheets"]` 与 `c1.metadata["sheets"] is source_meta["sheets"]` 旧实现均为 `True`；修复后均为 `False`。

### 修复

`make_chunk` 对已知的嵌套 key `sheets` 做 `list(meta["sheets"])` 独立浅拷贝（内部 per-sheet dict 只含标量，list 级拷贝即足够且无副作用）；其余 key 保持既有顶层 dict 拷贝行为，避免过度深拷贝。

## 💾 中严重度：写盘失败被吞成 ERROR 丢掉 Markdown（write-resilient）

### 问题

`_result_single` / `_result_multi` 把 `result.output_paths = self._write(...)` 直接放在结果构造里。`output_dir` 不可写时 `PermissionError` 冒泡，`_result_*` 的 `except` 把它升级成 `ERROR` 并**丢弃已生成好的内存 Markdown**，让调用方误以为"转换本身失败"。

### 修复

新增 `_write_resilient(result, paths, contents)`：写盘失败仅把状态降为 `DEGRADED` + `add_warning`，**保留 `result.markdown`**，`output_paths` 置空。两路径均接入。

## 🧯 中严重度：convert() 缺依赖时深埋 ImportError（guard）

### 问题

`convert()` 是绕过 router 的公开 API。router 正常会先 `available()` 守卫，但直连调用者缺 `mammoth/docx/pandas/openpyxl` 时，会在 builder 深处撞 `ImportError`，无可操作的提示信息。

### 修复

`convert()` 开头加 `if not self.available(): raise ValueError(_MISSING_DEPS_MSG)`，并补 `.doc` 需 `textract` 的守卫。

## 🔇 低严重度：--json 模式下 stdout 被进度提示污染（cli stdout purity）

### 问题

`cli.py` 导出分块后 `typer.echo(f"已导出分块：{path}")` 写到 stdout；当同时请求 `--json` 时，下游 `json.loads(sys.stdin)` 会被这条人类可读提示打断。

### 修复

该进度提示改走 stderr（`typer.echo(..., err=True)`），stdout 保持纯 JSON 流。
