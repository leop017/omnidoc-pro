# v0.1.9 — WebUI 下载功能

**OmniDoc Pro** v0.1.9 新增了 WebUI 转换结果的文件化下载能力：此前转换结果只以 Markdown 文本渲染在页面上（`output_dir` 默认为 `None`，从不落盘），用户只能手动复制文本；现在每次转换后自动生成下载文件，直接从页面获取。

## ✨ 新功能

### 1. "📥 下载转换结果" 区域

WebUI 右侧新增 `gr.File` 下载组件（多文件），点击"⚡ 开始转换"后自动列出所有可下载文件：

| 转换来源 | 下载文件 |
|---------|---------|
| Word/Excel（深度引擎） | 引擎按 `output_fmt` 直接写盘（`{文件名}_doc.md`，Excel 每 sheet 一个文件），复用既有 `output_dir` 落盘机制 |
| PDF/PPT/图片/URL 等（MarkItDown） | 自动补写一个 UTF-8 Markdown 文件，命名取自源文件名或 URL |
| 转换失败的源 | 跳过，不产生下载项 |

### 2. 下载文件命名规则（`_download_name`）

- **文件路径**：取 stem（`报告.docx` → `报告.md`）。
- **URL**：取域名+路径（`https://example.com/page.html` → `example.com_page.md`），剥离 URL 文件扩展名、裸域名保留。
- **清洗**：非法字符（`/\:*?"<>|` 与空格等）替换为 `_`，中文保留（`\w` Unicode 语义），空名回退 `untitled`。

## 🏗️ 实现说明

- **每次转换创建独立临时目录**（`omnidoc_webui_*`）并设为 `cfg.output_dir`，Word/Excel 的落盘完全复用 DeepEngine 既有的 `output_dir` 机制——这是 `DocumentResult.output_paths` 字段第一次真正被 UI 消费。
- **不违反"UI 薄壳"原则**（System Rule #2）：解析/清洗/分块逻辑仍在引擎层，UI 层只负责"把结果变成可下载文件"这一表现层职责；launch 逻辑仍收敛于 `webui.launch_app`。
- 转换失败的源不产生下载项；全部失败时下载区域清空。

## 🧪 测试覆盖

新增 `tests/test_webui.py`（12 个用例）：命名派生（路径 stem / URL 域名+路径 / 扩展名剥离 / 非法字符清洗 / 空名回退 / 中文保留）+ 文件收集（引擎写盘复用 / Markdown 补写 / 失败跳过 / 混合批次）。

## 📦 升级

```bash
pip install --upgrade omnidoc-pro
```

Windows 用户可从 [GitHub Releases](https://github.com/leop017/omnidoc-pro/releases) 重新下载 `omnidoc-web.exe`（内含本下载功能）。

## 已知限制

- exe 仍为 Windows 构建（CLI / WebUI）；Linux/macOS 请通过 `pip install` 安装 Python 版本。
- exe 内捆绑的 Gradio 版本取决于构建环境；本版本代码对 Gradio 5.x / 6.x 均兼容。
- 下载文件写入系统临时目录（每次转换一个 `omnidoc_webui_*` 子目录），由操作系统临时目录清理机制回收。
- LLM 增强功能需自行配置 API key（OpenAI / Ollama / 兼容 API）。
