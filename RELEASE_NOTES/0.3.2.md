# v0.3.2 — Excel 深度引擎 3 项零风险修复（HTML 错位 / Markdown 双转义 / 空表零诊断）

**OmniDoc Pro** v0.3.2 是 3 项针对 `omnidoc/engines/deep` 与 `omnidoc/engines/deep_engine.py` 的零风险缺陷修复。此前对全部源码的深度审计确认了 3 个真实缺陷：Excel 表头跨行合并时 HTML 表格输出错位、标准 Markdown 路径管道符双重转义破坏表格行、全空工作簿产生零诊断信息量的 ERROR 结果。三项修复均不改变任何既有成功路径，各附 1 个回归测试（基线 395 → 398 全过）。

## 🔧 修复清单（3 项）

### 1. 🧩 `ExcelBuilder._build_html_table`：表头跨行合并不再输出幽灵占位格（_excel.py）

**问题**：当表头单元格 `rowspan` 跨入正文行时（如 `A1:B2` 合并），body 循环对被覆盖格输出 `<td>&nbsp;</td>` 占位符。HTML 表格模型中格子被 `rowspan` 占据后再放 `<td>` 会把后续单元格挤进"幽灵列"，导致子表头与数据行整体错位。同函数内 body 级合并分支用 `continue` 跳过被覆盖格，表头分支是唯一不一致处。

**修复**：`header_covered` 命中时直接 `continue`（不再追加 `<td>&nbsp;</td>`），与 body 分支行为一致。

### 2. 📝 `ExcelBuilder._generate_md_standard`：管道符单次转义（_excel.py）

**问题**：标准 Markdown 路径 `_cell` 先经 `escape_md_cell`（`|` → `\|`），随后输出再过 `_escape_table_cells` 二次转义（`|` → `\|`），管道符最终变成 `\\|`。GFM 渲染时管道符前偶数个反斜杠不被视为转义，单元格被拆成多列，表格行损坏。增强路径 `_generate_md_via_html` 只转义一次——两条路径不一致，确认为移植回归。

**修复**：`_cell` 去掉 `escape_md_cell` 包裹，仅保留 `html_mod.escape`；由 `_escape_table_cells` 做唯一一次转义。换行单元格行为不变（终点同为字面 `<br>` 文本）。

### 3. 🩺 `DeepEngine._result_multi`：全空工作簿 ERROR 携带跳过原因（deep_engine.py）

**问题**：工作簿所有 sheet 为空时，`build()` 把原因记入 `skipped`（如 `("Empty", "工作表为空")`）而非 `errors`；`_result_multi` 空分支只遍历 `errors`，最终产生 `status=ERROR, errors=[], warnings=[]` 的零诊断结果——CLI / WebUI 只看到失败标志，无从得知原因。

**修复**：空分支在 `return` 前补遍历 `built.get("skipped", [])`，将跳过原因记入 `result.add_error`。混合"空 + 非空" sheet 场景行为不变（仍为 OK + warning）。
