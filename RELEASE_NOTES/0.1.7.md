# v0.1.7 — 分块元数据准确性修复

**OmniDoc Pro** v0.1.7 是 v0.1.6 的修复版本，修正了分块器中两处下游 RAG 消费者会直接读到的元数据错误，以及一处类型注解卫生问题。

## 🐛 Bug 修复

### 1. `MarkdownChunker` 的 `chunk_count` 元数据错误

**现象**：当 `max_chunk_size` 把单个标题子树切成 N 段时，每一段的 `chunk_count` 被写成 `groups * N`（组数 × 本组分段数），既不是真实的 chunk 总数，也不是组数。下游 RAG 消费者拿这个数字做 `i/N` 进度提示时会读到错误值。

**修复**（`omnidoc/processors/chunkers/markdown.py`）：先做一遍预计算，把每个 group 切分后的 `pieces` 列表都收集起来，再 `total = sum(len(pieces) ...)` 得到**真实的全局 chunk 总数**，第二遍按这个 total 生成 chunk。`chunk_count` 现在语义一致：「该 Document 分块后产生的 chunk 总数」。

**影响**：markdown 策略下下游 RAG 入库的元数据从错误值变为正确值。

### 2. `SentenceChunker` 的 `start_index` / `end_index` 偏移量精度

**现象**：原实现先贪心切分出 `chunks: list[str]`，再事后用 `text.find(body[:40], cursor)` 启发式地猜测每段在原文中的位置；`cursor = max(end - overlap, start + 1)` 语义含糊，`find` 返回的「位置 + body 长度」还可能因正文换行 / 多空格而错位。

**修复**（`omnidoc/processors/chunkers/sentence.py`）：
- 新增 `_Sentence` NamedTuple + `_split_with_offsets(text)`，切句时就记录每句的**真实起始偏移**；
- 贪心窗口改为携带 `(start_off, end_off)` 区间而非字符串；flush 时直接写成 `(首句start, 末句end)` 对；
- 重叠区重新锚定：`anchor = max(prev_start, prev_end - overlap)`，把上一段尾部 overlap 字符作为新窗口起点；
- chunk 正文直接由 `text[start:end]` 生成，彻底消除「事后 find 猜位置」的启发式。

**不变量**：`text[c.start_index:c.end_index] == c.text` 现在可被测试直接断言，未来任何改动破坏它都会立即失败。

### 3. `DocumentResult.add_error` 的 `-> Optional[None]` 类型注解

**现象**：`def add_error(self, message: str) -> Optional[None]` 在逻辑上等价于「总是返回 None」，与紧挨着的 `add_warning(self, message: str) -> None` 风格不一致，且语义有误导性。

**修复**（`omnidoc/core/document.py`）：`-> None`，删除末尾 `return None`，顺带清理了不再使用的 `Optional` import。

## 🧪 测试覆盖

`tests/test_chunkers.py` 新增 4 个回归测试：

| 测试 | 锁定行为 |
|------|----------|
| `test_chunk_count_is_real_total_when_split` | 单一子树被切多段时，每个 chunk 的 `chunk_count` == `len(chunks)` |
| `test_chunk_count_mixed_split_and_unsplit` | 混合切分 / 未切分场景，`chunk_count` 等于全局总数 |
| `test_offsets_match_source_slice` | `text[c.start_index:c.end_index] == c.text` 精确还原 |
| `test_offsets_contiguous_with_overlap` | 有 overlap 时相邻 chunk 的 `start_index` <= 前一 chunk 的 `end_index` |

## 已知限制

- exe 仍为 Windows 构建（CLI / WebUI）；Linux/macOS 请通过 `pip install` 安装 Python 版本。
- LLM 增强功能需自行配置 API key（OpenAI / Ollama / 兼容 API）。
- `max_chunk_size` 仅对 markdown 策略生效；fixed / sentence 策略不受该字段影响。
