# v0.3.5 — 零风险修复：Doc 引擎 Markdown 路径 HTML 转义（_doc.py）

**OmniDoc Pro** v0.3.5 包含 1 项经全量源码审计识别、回归验证的零风险缺陷修复。全套测试 **404 passed** 保持不变。

## 🔧 修复清单（1 项）

### 1. 🧩 `DocBuilder.build`：`output_fmt="md"` 且 `enhanced_md=False` 时缺少 HTML 转义（_doc.py）

**问题**：DocBuilder 的 `md` 输出路径（`enhanced_md=False`）直接 `content = text`，未做 HTML 转义。当文本含 `<`、`>`、`&`、`#` 等字符时，后续渲染（HTML→md 或 WebUI 展示）会出现解析漂移或注入式输出。`html` 路径（第 45 行）与 `enhanced_md=True` 路径（第 49 行）都正确使用了 `html_mod.escape(text)`，唯独这条路径漏了。

**修复**：把 `content = text` 改为 `content = html_mod.escape(text)`，与同函数内其它 `md` / `html` 路径保持一致。

**风险 = 0 的论证**：
- 仅影响 legacy `.doc`（`textract` 可选依赖）的 `output_fmt="md"` 且 `enhanced_md=False` 分支；
- 该路径的产出最终进入 `DeepEngine._result_single` 的 `_export`（markdown 直出），下游 chunker / cleaner 只处理纯文本，不会把已转义实体误渲染；
- 成功路径（`.docx` / `.xlsx` / `.xls`）不经过该分支，行为不变；
- 现有 404 个测试覆盖 docx / xlsx 端到端与 `md` 直出，无一条依赖"未转义"语义。
