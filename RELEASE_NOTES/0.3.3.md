# v0.3.3 — Excel 增强 Markdown 合并单元格腿范围修复（_excel.py）

**OmniDoc Pro** v0.3.3 是 1 项针对 `omnidoc/engines/deep/_excel.py` 的零风险缺陷修复。此前对全部源码的深度审计确认了 1 个真实缺陷：增强 Markdown 路径（`ExcelBuilder._generate_md_via_html`）中合并单元格的"腿"范围 off-by-one，导致主格值泄漏进本应空白的合并区，列布局错位。修复后行为与同文件 HTML 路径 `_build_html_table` 完全对齐，无合并场景行为不变。

## 🔧 修复清单（1 项）

### 1. 🧩 `ExcelBuilder._generate_md_via_html`：合并腿范围 off-by-one + 腿值双重包裹（_excel.py）

**问题**：当工作表存在 `rowspan > 1` 或 `colspan > 1` 的合并单元格时，`_generate_md_via_html`（`output_fmt="md"` 且 `enhanced_md=True` 路径）渲染错位。两处叠加缺陷：

1. **腿范围 off-by-one**：`for r in range(cell_info.rowspan)` + `for c in range(cell_info.colspan)` 把主格所在行/列计入"合并腿"范围。2×2 合并（主格 `(1,1)`）本应只标记额外行/列 `(2,2)`，实际却把 `(1,1)`、`(1,2)`、`(2,1)` 全部当作腿。
2. **腿值双重包裹**：腿值塞入 `f"<{tag}>{cell_value}</{tag}>"`（已带标签的整格 HTML），后续消费端 `cells.append(span_val)` 再套一层标签，形成 `<td><td>value</td></td>` 嵌套。

**真实现象**（2×2 合并 `A1:B2` + 第 3 列 `C3`，`enhanced_md=True`）：

```
# 修复前（错误）
| H1 | H1 | C3 |
| --- | --- | --- |
| H1 | H1 | c3_2 |   ← 主格值 H1 泄漏到合并腿

# 修复后（正确）
| H1 | C3 |
| --- | --- |
| c3_2 |   ← 合并腿渲染为空
```

**修复**：
- 腿范围 `range(0, span)` → `range(1, span)`（与同文件 `_build_html_table` L406-408 参照实现一致）；
- 腿值 `f"<{tag}>{cell_value}</{tag}>"` → `True`（布尔标记）；
- 消费端 `if span_val is not None: cells.append(span_val)` → `if span_val: continue`（合并腿渲染为空占位，与 HTML 路径布尔消费语义对齐）。
