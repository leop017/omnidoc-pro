# v0.1.8 — Gradio 6 兼容性修复

**OmniDoc Pro** v0.1.8 是 v0.1.7 的修复版本，解决了 v0.1.7 发布的 Windows exe（捆绑 Gradio 6.0.0）启动即崩溃的问题：Gradio 6 对组件参数和主题参数做了破坏性变更，而代码按 Gradio 5.x 的 API 编写。

## 🐛 Bug 修复

### 1. `gr.Markdown(show_copy_button=True)` 在 Gradio 6 下崩溃

**现象**：Gradio 6 移除了 `Markdown` 组件的 `show_copy_button` 参数，WebUI 构建时直接抛出 `TypeError: Markdown.__init__() got an unexpected keyword argument 'show_copy_button'`，导致从 GitHub Releases 下载的 `omnidoc-web.exe` 无法启动（`[PYI-xxxx:ERROR] Failed to execute script 'webui'`）。

**修复**（`omnidoc/ui/webui.py`）：移除 `show_copy_button=True`。

### 2. `theme` 参数的版本差异

**现象**：Gradio 6.0.0 将 `theme` 从 `Blocks()` 构造器迁移到了 `launch()` 方法——在 6.x 下传给 `Blocks()` 会发出 UserWarning，但 `launch()` 在 5.x 下**没有** `theme` 参数，直接传会 TypeError 崩溃。

**修复**：新增 `_theme_kwargs()` 按 Gradio 主版本号返回正确的参数形态（6.x 返回 `{"theme": gr.themes.Soft()}`，5.x 返回空），Soft 主题在两个大版本下均保留。

### 3. launch 逻辑收敛到 webui 层

**重构**（`omnidoc/ui/webui.py` + `omnidoc/ui/cli.py`）：新增 `launch_app()` 统一封装 `Blocks.launch()` 调用（含 theme 版本注入），`webui.main` 与 `cli.cmd_webui` 共用；CLI 保持「薄壳」设计，launch 逻辑只存在于 `webui.py` 一处。

## 🧪 测试覆盖

- 本地 gradio 5.50.0 实测：`build_app()` 构建 + `launch_app()` 启动，HTTP 探测返回 200。
- Gradio 6.0.0（exe 内捆绑版本）：`show_copy_button` 已移除、`theme` 已迁移至 `launch()`，两处崩溃点均消除。

## 已知限制

- exe 仍为 Windows 构建（CLI / WebUI）；Linux/macOS 请通过 `pip install` 安装 Python 版本。
- exe 内捆绑的 Gradio 版本取决于构建环境；本版本代码对 Gradio 5.x / 6.x 均兼容。
- LLM 增强功能需自行配置 API key（OpenAI / Ollama / 兼容 API）。
