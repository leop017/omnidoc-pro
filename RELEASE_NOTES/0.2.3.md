# v0.2.3 — 多 sheet 文件保护 + 分块偏移 round-trip + 图片 URL 净化

**OmniDoc Pro** v0.2.3 是针对 RAG 产物正确性的二轮修复。基于二次深度代码评估，修复了 1 个高严重度问题（多 sheet Excel 文件被覆盖损坏）、1 个中严重度问题（Markdown 分块在缩进内容下偏移漂移），以及 1 个中严重度问题（LLM 图片描述的 URL 标题泄漏）。全部 366 个测试通过，ruff 全部通过。

## 🛡️ 高严重度：多 sheet Excel 文件被覆盖（H1）

### 问题

`ConversionController._sync_written_files` 在 pipeline 清理后，把**整篇** `result.markdown` 写回 `result.output_paths` 里的**每一个** `.md` 文件。多 sheet Excel 的每个 sheet 各自一个文件（`report_SheetName.md`），但 `result.markdown` 是**所有 sheet 的拼接**。结果：每个 sheet 文件都被整篇拼接内容覆盖——sheet 级输出被破坏。

**端到端验证**：构造多 sheet `.xlsx` + `output_dir`，`convert` 后 2/2 sheet 文件内容均被整篇拼接 Markdown 覆盖。

### 修复

`_sync_written_files` 仅在**恰好 1 个** `.md` 输出路径时同步（单文档整篇写回是安全且预期的）。多 sheet（2+ 个 `.md`）跳过同步，保留各 sheet 的原始（正确）内容。新增 `TestSyncWrittenFiles` 3 例回归测试（单文件同步 / 多文件不碰 / 空路径 noop）。

## 🔢 中严重度：分块偏移在缩进内容下漂移（M1）

### 问题

`MarkdownChunker` 用 `_render` 把 heading + paragraph 用 `"\n\n"` 拼接，再用 `doc.text.find(text[:40], cursor)` 定位偏移。当源文本使用**单换行**（而非 `\n\n`）或**缩进**（代码块 / 嵌套列表）时，`find` 首 40 字符失败 → 偏移漂移到 0 → 后续 chunk 的 `start_index` / `end_index` 全部错位。`chunk.text`（归一化渲染文本）与 `doc.text[start:end]`（真实切片）不再相等，破坏 RAG 下游按偏移回溯原文的契约。

**探针验证**：缩进代码块 + 嵌套列表 + 长缩进切分场景，旧实现 0 mismatch 修复后全部通过，经典多 section 场景无回归。

### 修复

- `_heading_elements_from_text` 在每个 derived 元素上记录**精确源字节偏移**（`metadata["start"]` / `metadata["end"]`）。
- 新增 `_group_span`：校验组内元素跨度单调后返回精确源区间 `(start, end)`。
- `chunk` 方法优先用源切片 `doc.text[start:end]` 作为 `chunk.text`（保证 round-trip）；引擎元素（无偏移）回退到旧的 render + find 路径。
- 切分场景用 O(k) 前缀和计算每个 piece 的偏移（O(k²) → O(k)）。

## 🔗 中严重度：LLM 图片 URL 标题泄漏（M3）

### 问题

`_describeable_image_refs` 把 `![alt](url)` 里括号内**整段**直接当 URL 送给 vision API。当图片引用带 CommonMark 标题（`![alt](url "title")`）或尖括号（`![alt](<url with spaces>)`）时，标题 / 尖括号会泄漏进 URL，导致 vision API 返回 400 或无法解析。

### 修复

新增 `_bare_image_url` 辅助：剥离尾部引号标题与尖括号，还原 API 真正需要的裸 URL。`_describeable_image_refs` 用它净化每个 `inner`。新增 4 例回归测试（双引号标题 / 单引号标题 / 尖括号 / 裸 URL 不变量）。
