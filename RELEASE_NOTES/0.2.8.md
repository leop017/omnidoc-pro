# v0.2.8 — Ollama provider 感知门控 + 全角句界正则 + 图片 MIME 魔数嗅探

**OmniDoc Pro** v0.2.8 是一个经两轮探针验证的三项修复批次：Ollama 无 Key 场景的 LLM 增强门控、SentenceChunker 全角终止符分句、`_to_data_uri` 未知扩展名魔数嗅探。每项修复均以"不引入新问题"为前提，并附 22 个新回归测试。

## 🐞 修复清单（3 项）

### 1. 🤖 LLM：Ollama 无 Key 时图像描述不再被跳过（llm_service.py / markitdown_engine.py）

**问题**：0.2.6 对 `LlmSettings.is_usable()` 的 provider 感知修复是死代码（全库无运行时调用方）。4 处运行时门控（`build_client` / `LlmEnhancer.enhance` / `markitdown_engine._build_llm_kwargs` / `test_llm_connection`）仍硬性要求 `api_key`，导致 Ollama 本地端点（接受占位符 key）无法启用 LLM 图像描述。

**修复**：在 `omnidoc/ai/llm_service.py` 新增 provider 感知 helper 并同步全部 4 处调用点：

- `_api_key_ok(llm)`：`provider == "ollama"` 时放行；原始 dict 配置（无 `provider` 键，测试 / 手工构建）回退到 OpenAI 历史严格行为，与既有测试完全兼容。
- `_placeholder_api_key(llm)`：Ollama 空 key 自动填 `"ollama"` 占位符。

### 2. ✂️ 分块：SentenceChunker 全角终止符（！？）不分句（sentence.py）

**问题**：边界正则 `[.!?。!?]` 把 ASCII `!`/`?` 写了两遍，漏掉全角 `！`(U+FF01)/`？`(U+FF1F)——多段落中文文本只分出预期句数的一半（探针验证：4 句只出 2 句）。

**修复**：正则改为 `(?<=[.!?。！？])\s+`，docstring 同步。已知限制不变：标点后无空白的连排中文仍不切分（启发式要求后跟空白）。

### 3. 🖼 LLM：未知扩展名文件的 MIME 魔数嗅探（llm_service.py）

**问题**：`_to_data_uri` 的 `mimetypes.guess_type(url)[0] or "image/png"` 兜底会把未知扩展名/无扩展名的**非图片**文件内联为 `data:image/png` URI 发给视觉 API（必然 400），削弱 0.2.7 的守卫承诺；但简单删除兜底又会让"无扩展名真图片"回归 400。

**修复**：新增 `_sniff_image_mime()`（PNG/JPEG/GIF/BMP/WEBP 魔数嗅探），`_to_data_uri` 改为：已知 MIME 短路 → 未知时读文件头嗅探 → 仅真图片内联，两头兼顾。
