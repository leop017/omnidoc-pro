# v0.3.9 — 零风险修复：图片 URL 组合形态剥离 + WebUI 离线模式 LLM 门禁追平

**OmniDoc Pro** v0.3.9 包含 2 项零风险缺陷修复，分别集中在 LLM 图片 URL 净化与 WebUI 配置构建路径。全套测试 **421 passed**（410 基线 + 11 条新增回归用例），`ruff check .` 全绿。

## 🔧 修复清单（2 项）

### 1. 🔗 `_bare_image_url()` 互斥分支导致 `![alt](<url> "title")` 组合形态剥离不干净

**问题**：
- [`omnidoc/ai/llm_service.py`](omnidoc/ai/llm_service.py) 的 `_bare_image_url()` 原实现用 if/elif **互斥分支**处理"剥 angle brackets"和"剥 quoted title"。
- CommonMark 允许 `![alt](<url> "title")` 组合形态（quoted title 出现在 closing `>` **之后**）。修复前，输入 `<https://example.com/a.png> "My Title"` 时走 title 剥离分支，结果仍残留 `< >`。
- 后果：残留的 `< >` 被喂给 vision API，触发 **400 Bad Request**。

**实测**（修复前）：

| 输入 | 修复前 | 修复后 |
|---|---|---|
| `<https://example.com/a.png>` | `https://example.com/a.png` ✅ | `https://example.com/a.png`（不变） |
| `https://example.com/a.png "My Title"` | `https://example.com/a.png` ✅ | `https://example.com/a.png`（不变） |
| `<https://example.com/a.png> "My Title"` | `<https://example.com/a.png>` ❌（残留 brackets） | `https://example.com/a.png` ✅ |
| `https://example.com/a.png` | `https://example.com/a.png`（不变） | `https://example.com/a.png`（不变） |

**修复**：
- 把 title 剥离与 angle brackets 剥离改为**串行两步**（不再互斥）：先 `re.sub` 剥掉 trailing quoted title，再 unwrap `< >`。

**风险 = 0 的论证**：
- 仅重排两步执行顺序，**不新增分支、不改变任何单一形态的返回值**；
- 既有 4 条测试（[`tests/test_llm_service.py`](tests/test_llm_service.py) L199-230）全部覆盖无 title 或无 brackets 的**单一形态**，修复后逐条不变；
- 没有既有测试 pin 住 `<url> "title"` 这个错误组合，因此本次修复不影响任何既有断言。

### 2. ⚙️ WebUI `_build_config()` 未合并 `offline_mode`，与 CLI 语义不一致（防御性缺口）

**问题**：
- [`omnidoc/ui/webui.py`](omnidoc/ui/webui.py) 的 `_build_config()` 原实现只写 `cfg.llm.enabled = bool(llm_enabled)`，**没有合并 `offline_mode`**。
- 对比 CLI [`omnidoc/ui/cli.py`](omnidoc/ui/cli.py) 的 `_resolve_llm()` 正确写 `enabled=enabled and not offline`。
- 后果：WebUI 勾选离线模式 + LLM 开关 ON 时，扁平 dict 同时满足 `offline_mode=True` 且 `llm.enabled=True`。
- 当前 `_build_llm_kwargs` 与 `LlmEnhancer.enhance` 都读 `offline_mode` 做门禁，所以**行为正确**；但这是实现追平契约的防御性缺口——任何仅读 `llm.enabled` 的下游都会误判 LLM 可用。

**修复**：
- `cfg.llm.enabled = bool(llm_enabled) and not bool(offline_mode)`，与 CLI 语义对齐。

**风险 = 0 的论证**：
- 仅改 1 行；
- 当前可观测输出 **100% 不变**（`enhance` 门禁双 key 兜底，`offline_mode=True` 仍会跳过 LLM 调用）；
- [`tests/test_webui.py`](tests/test_webui.py) 不覆盖 `_build_config`，无任何既有断言受影响。
