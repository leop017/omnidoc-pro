# v0.2.9 — 降级链 DEGRADED 语义 + 广度依赖完整化 + Ollama 入口 + CSV 排重 + 分块异常标记

**OmniDoc Pro** v0.2.9 是第一阶段(单向安全)的 5 项修复批次。每项都以"不引入新回归"为前提,全量回归 `395 passed, 6 subtests passed` + `ruff All checks passed` 基线不回退。

## 🐞 修复清单(5 项)

### 1. 🔻 降级链:DEGRADED 结果不再被后续 ERROR 覆盖(conversion.py)

**问题**:`_convert_with_fallback` 的循环判据 `if result.status == ConversionStatus.OK` 不认 DEGRADED。当深度引擎返回 **DEGRADED**(部分成功,markdown 非空)时,不会 `return`,继续遍历;广度引擎若 `available()` 为 False(基础安装无 markitdown),`last` 被覆写成**空 ERROR** → 用户拿不到任何可下载文件,CLI exit 1。若装 `[full]`,广度引擎真跑,返回自己的 DEGRADED,深度引擎的 per-sheet 文件/告警被静默丢弃。

**修复**:判据改为 `in (OK, DEGRADED)`;`idx > 0` 时只有原为 OK 的才降级为 DEGRADED(避免把引擎自返的 DEGRADED 重复处理)。M1 回归测试(`test_placeholder_markdown_error_not_misjudged_as_degraded`)只测 ERROR 路径,不受影响。

### 2. 📦 广度依赖:`[full]` 改用 `markitdown[all]`(pyproject.toml / README)

**问题**:`[full]` 引的是裸 `markitdown`(不带可选组),README 首推的 `omnidoc-pro[full]` 实际缺 PDF/PPTX/.msg/音频/YouTube 解析器——恰好是 README 宣传的广度格式。

**修复**:`full` extra 由 `omnidoc-pro[markitdown,...]` 改为 `omnidoc-pro[markitdown-all,...]`(复用已存在的 `markitdown-all` extra)。核心依赖已含 Word/Excel/图片解析,故仅 `full` 安装体积变大,不影响基础安装。README 依赖描述同步改准。

### 3. 🤖 LLM:Ollama `provider` 在 CLI/WebUI 可达(cli.py)

**问题**:`LlmSettings` 有 `provider` 字段,但 CLI 的 `_resolve_llm` 不传它,`omnidoc/ui/` 下零处出现 `provider`。Ollama 用户无法通过 CLI 指定 `provider="ollama"`,只能靠填假 key 或改 Python API。

**修复**:CLI `convert` 加 `--llm-provider`(默认 `openai`),`test-llm` 加 `--provider`;`_resolve_llm` 透传 provider 到 `LlmSettings`,`cmd_test_llm` 把 provider 透传给 `test_llm_connection`(Ollama 门控现在生效)。新增 `_PROVIDER_ENV = "OMNIDOC_LLM_PROVIDER"` 环境变量回退。

### 4. 🧹 清洗:CSV 不再被误删连续重复行(pipeline.py)

**问题**:`_TABLE_FORMATS` 不含 `.csv`,所以 `remove_duplicate_headers` 对 CSV 恒为 True,`_dedupe_consecutive_lines` 删除任何"连续且完全相同"的非空行 → 连续重复的 CSV 数据行消失。管道注释明确"真实数据行必须被 scope out",`.csv` 是漏网之鱼。

**修复**:`_TABLE_FORMATS` 加 `".csv"`。单调安全:只可能少删行,不可能多删。

### 5. 📊 分块:异常路径置 `rag_failed`(pipeline.py)

**问题**:分块阶段的 `except` 只 `add_warning`,不置 `result.rag_failed = True`;而 0-chunks 路径已正确置位。分块异常意味着没有 RAG-ready 分块,应与 0-chunks 路径同等标记。

**修复**:异常路径对齐 0-chunks——OK→DEGRADED + `rag_failed = True`。已确认 LLM 增强器不改写 status,不会被抵消。
