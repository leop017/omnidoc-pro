# v0.2.7 — LLM 图像描述本地非图片文件守卫（零风险）

**OmniDoc Pro** v0.2.7 是一个单一零风险加固批次：在 LLM 图像描述增强器（`omnidoc/ai/llm_service.py` 的 `_to_data_uri`）中，对本地**非图片**文件路径（`.txt` / `.md` / `.pdf` / `.csv` 等）添加 MIME 类型守卫，避免将其 base64 内联为 `data:` URI 并发送给视觉 API 导致 400 错误。

## 🐞 修复清单（零风险，1 项）

### 🖼 LLM：`_to_data_uri` 本地非图片文件原样透传（llm_service.py）

**问题**：当 Markdown 中的图片引用指向一个本地**非图片**文件时（例如 `![alt](notes.txt)`），`_to_data_uri` 会把该文件读取并 base64 编码，生成 `data:text/plain;base64,...` 这样的 URI，并将其作为 `image_url` 发送给视觉 LLM 接口。视觉 API 只接受图像数据，请求必然返回 400 / 解码失败，整批 LLM 图像增强触发错误告警。

**修复**：添加 `if mime.startswith("image/")` 守卫——只有真正的图像文件才走 base64 内联路径；非图片文件原样返回原始 URL，交由上层按 http(s) 或失败处理。对真正的图片文件（`image/*`）**行为完全不变**，零回归风险。

```python
if os.path.exists(url):
    mime = mimetypes.guess_type(url)[0] or "image/png"
    if mime.startswith("image/"):          # ← 新增守卫
        with open(url, "rb") as f:
            b64 = base64.b64encode(f.read()).decode()
        return f"data:{mime};base64,{b64}"
return url
```
