# v0.1.5 — 安全加固 + 鲁棒性修复

**OmniDoc Pro** v0.1.5 是 v0.1.4 的修复版本，解决了四个已验证的真实问题：`.xls` 合并单元格解析崩溃、SSRF 检查可被 DNS 多记录绕过、Markdown 分块标题偏移错算、以及 Release 工作流中 exe 产物来源分支漂移。

## 🐛 Bug 修复

### `.xls` 合并单元格解析崩溃（BUG-1，高影响）

**现象**：解析 `.xls`（旧版二进制 Excel）文件时，`xlrd.open_workbook(..., formatting_info=True)` 对缺少 BIFF8 格式信息的现代 Excel 文件抛出 `XLRDError`，异常发生在 try 块之外，导致整个转换直接崩溃而非优雅降级。

**修复**：`_load_merged_cache_xls` 将 `open_workbook` 与缓存构建循环全部包进 try/except，失败时记录 warning 并返回 `None`，与 `.xlsx` 路径（`_load_merged_cache`）行为一致；`staticmethod` 内改用模块级 `get_logger()` 而非 `self.logger`。

**影响**：损坏或格式不全的 `.xls` 文件不再中断转换，合并单元格读不出来时自动降级为"无合并"，其余单元格内容仍可正常解析。

### SSRF 检查可被 DNS 多记录绕过（BUG-3，中影响）

**现象**：MarkItDown 引擎的 `_resolve_ip` 只取 `socket.getaddrinfo` 返回的**第一条**记录做内网判断。攻击者可用域名绑定多个 A 记录（其中一条指向公网、一条指向 `127.0.0.1`/`10.x`），只要第一条恰好是公网地址就能绕过 SSRF 防护。

**修复**：`_resolve_ip` 现返回**全部**解析到的 IP 列表；新增 `_is_private_ip` 辅助函数；`_is_safe_url` 只要**任一** IP 落在内网/回环/链路本地/保留/未指定/多播区间即拒绝。

**影响**：堵住 DNS rebinding / 多 A 记录绕过向量，URL 解析路径更安全。

### Markdown 分块标题偏移错算（BUG-5，中影响）

**现象**：当引擎只填充 `Document.text` 而 `elements` 为空时，`MarkdownChunker` 走 `_heading_elements_from_text` 回退路径解析出纯文本标题（如 `章节A`），但 `_render` 直接拼接纯文本而不还原源文中的 `#`/`##` 前缀，导致 `doc.text.find(rendered[:40], cursor)` 命中失败、chunk 偏移量整体错位。

**修复**：`_heading_elements_from_text` 在 `Element.metadata` 中记录标题级别（`level`），分组与 `_render` 据此重建 `#` 前缀使渲染文本与源文逐字节匹配；`metadata["header"]` 仍保持纯文本以满足既有测试断言。

**影响**：markdown 策略产出的 chunk `start`/`end` 偏移精确对齐源文，RAG 下游可正确定位。

### Release 工作流 exe 产物来源分支漂移（BUG-2，中影响）

**现象**：`.github/workflows/release.yml` 中 `build-exe` 与 `release` 两个 job 的 `actions/checkout` 未指定 `ref: ${{ inputs.ref }}`（而 `test`/`build` job 有）。手动 Run workflow 输入 tag 时，wheel 从该 tag 构建，但 exe 却默认从主分支 checkout 构建，造成同一 release 的附件来自不同代码版本。

**修复**：两个 job 的 checkout 补齐 `ref: ${{ inputs.ref }}`，保证 wheel 与 exe 始终来自同一 tag。

**影响**：手动触发的 release 附件版本一致性得到保证。
