# v0.2.0 — RAG 分块结果可下载 + 参数前置校验

**OmniDoc Pro** v0.2.0 让 WebUI 的「启用 RAG 分块」选项终于有了可见的输出通道：此前勾选分块后 `result.chunks` 虽然被管线生成，但界面没有任何展示或下载入口，用户感知不到分块是否执行、结果在哪里。本版本补齐了分块结果导出（JSONL），并新增了分块参数前置校验——非法参数不再静默失败、而是转换前即被拦截。

## ✨ 新功能

### 1. 分块结果导出（`_write_chunks`）

转换勾选「启用 RAG 分块」后，下载区（gr.File）新增 `*.chunks.jsonl` 文件，**每个携带分块的源一个文件**，文件名沿用 `_download_name` 命名规则：

| 源类型 | 下载文件 |
|--------|---------|
| `报告.docx` | `报告.chunks.jsonl` |
| `https://example.com/page` | `example.com_page.chunks.jsonl` |

每行一个 JSON 对象，字段完整，可直接喂给 embedding 管线：

```json
{"source": "报告.docx", "engine": "deep", "start_index": 0, "end_index": 512,
 "metadata": {"chunk_index": 0, "chunk_count": 11}, "text": "..."}
```

- 不含分块的结果（未启用分块 / 转换失败）不产生 chunks 文件，与 Markdown 下载行为一致
- 分块统计在界面上直接可见：
  - **状态栏**：每个结果行追加 `· 分块=N`
  - **计数框**：`N 个源 · M 个分块`

### 2. 分块参数前置校验（`_validate_chunking`）

校验规则与分块器后端（`FixedSizeChunker` / `SentenceChunker` / `MarkdownChunker`）完全一致，在 `_on_convert` 入口提前拦截：

| 策略 | 校验项 | 违例示例 |
|------|--------|----------|
| fixed / sentence | `chunk_size > 0` | 0 / 负数 / 空（清空输入框） |
| fixed / sentence | `0 ≤ chunk_overlap < chunk_size` | `overlap ≥ size`、负数 |
| markdown | `chunk_max_size` 非负（0=不切分） | 负数 |

非法输入时直接返回「❌ 分块参数校验失败：…」，不再空跑整个批次。替代了原先"分块阶段静默抛 ValueError → 仅一条小字 warning"的糟糕体验。

### 3. 附带修复

- `_build_config` 对空值防御：用户清空 Number 输入框时 Gradio 返回 `None`，原先 `int(None)` 会直接崩溃，现在归一化为 0
- `chunk_size` / `chunk_overlap` 标签注明作用范围（仅 fixed/sentence），与校验规则呼应，减少误操作

## 🏗️ 实现说明

- **不违反"UI 薄壳"原则**（System Rule #2）：分块逻辑仍在 `ProcessingPipeline._chunk`，UI 层只负责"把 chunks 变成可下载文件 + 校验参数 + 展示统计"这三项表现层职责
- 校验复用 `_download_name` 命名契约（`安全名.扩展名`），与 v0.1.9 的 Markdown 下载文件命名保持一致
- 不依赖 `openai` / `markitdown` 等任何可选依赖，纯标准库 + 既有管线

## 🧪 测试覆盖

新增 14 个用例（`tests/test_webui.py`）：

- `TestValidateChunking`（10 个）：禁用短路 / 合法参数 / 零值 / 负值 / 越界 overlap / markdown 忽略 size+overlap / markdown 负 max / 清空输入框（None）
- `TestWriteChunks`（4 个）：正常写 JSONL / 无分块跳过 / 混合批次 / 中文源文件名

## 📦 升级

```bash
pip install --upgrade omnidoc-pro
```

Windows 用户可从 [GitHub Releases](https://github.com/leop017/omnidoc-pro/releases) 重新下载 `omnidoc-web.exe`（内含本分块导出与校验能力）。

## 已知限制

- exe 仍为 Windows 构建（CLI / WebUI）；Linux/macOS 请通过 `pip install` 安装 Python 版本。
- 分块 JSONL 文件写入系统临时目录（每次转换一个 `omnidoc_webui_*` 子目录），由操作系统临时目录清理机制回收。
- LLM 增强功能需自行配置 API key（OpenAI / Ollama / 兼容 API）。
