# v0.2.6 — 发布脚本 / 配置 / 健壮性零风险加固（11 项）

**OmniDoc Pro** v0.2.6 是一次「仅零风险修复」的加固批次。对 0.2.5 之前遗留的 38 条疑似问题逐一做了**真实性复核 + 修复必要性评估 + 回归探针验证**，筛出 **11 条零风险修复**（任何一条都不会改变既有成功路径的行为，只做「降级 / 防御 / 兜底 / 一致性」），并全部通过 373 个既有测试 + 6 个 subtests。其余疑似项按「非零风险 / 理论边角 / 误报」归类，**不在本版本修复**，列为后续版本候选。

## 🐞 修复清单（全部零风险，11 项）

### 🔧 #2 发布脚本：sdist 清理判据永假（release.py）

`cmd_build` 清理 `dist/` 时写的是 `f.suffix in (".whl", ".tar.gz")`。但 `Path.suffix` 对 `omnidoc_pro-0.2.5.tar.gz` 只返回 **`.gz`**（最后一段），`.tar.gz` 永远匹配不到 → sdist 从不被清理，累积旧产物。改为 `f.name.startswith("omnidoc_pro") and f.name.endswith((".whl", ".tar.gz"))`，命中后 `unlink()`。

### 🏷 #4 发布脚本：`all` 子命令透传 `cmd_exe` 时 AttributeError（release.py）

`cmd_exe` 直接读 `args.skip_cli` / `args.skip_web`，但这两个属性**只在 `exe` 子命令的 parser 上定义**；从 `all` 透传时 `args` 上根本没有这两个属性 → `AttributeError`。改为 `getattr(args, "skip_cli", False)` / `getattr(args, "skip_web", False)`，兜底 False 让两个 spec 都构建。

### 📝 #5 控制器：`_sync_written_files` 写盘失败中止整批（conversion.py）

`_sync_written_files` 对「恰好 1 个 .md」场景做 `Path(md_paths[0]).write_text(...)` 回写，但 `write_text` 未做异常兜底。任何 `PermissionError`（只读文件 / 锁定文件 / 权限不足）都会从该函数冒泡、把整批转换中止。包成 `try/except OSError`，失败时 `result.add_warning("清理后内容回写失败，保留引擎原始文件：...")`，**保留引擎原始文件、不中止批次**。

### 📄 #8 分块导出：`export_chunks_jsonl` 非可序列化 metadata 截断 JSONL（document.py）

`json.dumps(chunk, ...)` 未指定 `default`，只要 `chunk.metadata` 里有 `datetime` / `set` 等不可 JSON 序列化对象，`json.dumps` 抛 `TypeError`，JSONL 文件被**截断到该条为止**。补 `default=str`，把未知对象回退成 `str()`，保证整篇 JSONL 一定写满。

### 🎯 #3 CLI：`typer=None` 时模块导入直接崩（cli.py）

`cmd_convert` / `cmd_test_llm` / `cmd_webui` 三个函数在模块顶层定义，其默认参数 `typer.Argument(...)` / `typer.Option(...)` 在**导入时求值**。当 `typer` 缺失（`try import typer` 失败 → `typer = None`）时，求值 `None.Argument` 直接 `AttributeError`，**整个 `omnidoc.ui.cli` 模块导不进**，连不上 Typer 的用户连友好提示都看不到。把这三个 `cmd_*` 函数移入 `if typer is not None:` 块内（纯 helper `_resolve_llm` / `_build_config` / `_unique_cli_name` / `_render` 仍在顶层保留），`app.command(...)` 注册随函数下沉。`typer=None` 时模块正常导入、`app` 为 `None`，`main()` 走到友好降级分支。

> 顺带在 `cmd_webui` 里补上 `_cleanup_stale_tempdirs()` 调用（#L16）：WebUI 启动前清理上次进程残留的临时目录。

### 🤖 #6 配置：Ollama `is_usable()` 误拒（config.py）

`LlmSettings.is_usable()` 原为 `bool(self.enabled and self.base_url and self.api_key and self.model)`，对 Ollama 本地 OpenAI 兼容端点（**不需要 `api_key`**）误判为不可用 → 用户启了 Ollama 但 LLM 增强永远不走。改为：

```python
if self.provider == "ollama":
    return True
return bool(self.api_key)
```

（前提仍是 `enabled` / `base_url` / `model` 全非空。）

### ✅ #7 配置：`strategy` 改 `Literal` 校验（config.py）

`ChunkingSettings.strategy` 原为 `str`，任意字符串都能通过 Pydantic，下游 chunker 路由时才炸。改为 `Literal["fixed", "sentence", "markdown"]`，非法值（如 `"bogus"`）在**构造配置**那一刻就抛校验错误，不再流入运行时。

### 🛡 #L7 LLM：`max_concurrency` 防御（llm_service.py）

`_run_bounded` 原为 `int(llm.get("max_concurrency", DEFAULT))`。当 `max_concurrency` 键**存在但为 `None`**（上游配置合并 / 序列化副作用）时，`int(None)` 抛 `TypeError`，整批 LLM 增强崩。改为：

```python
raw = llm.get("max_concurrency") or DEFAULT_MAX_CONCURRENCY
max_concurrency = max(1, int(raw))
```

`or` 让 `None` / 空串 / `0` 都回落到默认值，`max(1, ...)` 保证信号量至少 1。

### 🔁 #L4 接口：URL 与本地路径格式判定大小写一致（interfaces.py）

`_source_format` 本地路径分支有 `.lower()`，URL 分支没有。`https://example.com/A.B.DOCX` 返回 `A.B.DOCX`，下游按大小写匹配 `docx` 时漏判。URL 分支补 `.lower()`，两分支一致。

### 🧰 #L18 发布脚本：`ensure_twine` 覆盖 PYTHONPATH（release.py）

`ensure_twine` 写 `os.environ["PYTHONPATH"] = str(TOOLS)` 直接**覆盖**用户已设置的 `PYTHONPATH`，把用户自己装的包路径丢掉。改为 `os.pathsep.join([str(TOOLS)] + ([os.environ["PYTHONPATH"]] if os.environ.get("PYTHONPATH") else []))`，保留原条目再追加 `.tools/`。

## 📌 未修项（非零风险 / 边角，列后续版本）

以下条目在本批次评估中识别，但**修复代价 / 回归风险不为零**，**不在 0.2.6 落地**，列入后续版本候选：

- **#1 DEGRADED-discard**：`_convert_with_fallback` 仅在 `result.status == OK` 时返回结果，`DEGRADED` 状态的 markdown / chunks 直接被丢。修复需**多引擎诊断合并**（保留所有引擎的 warning 与已生成产物），属中风险语义变更。
- **#13 部分写盘孤儿文件**：`_write` 写 N 个文件时，若第 k 个失败，前 k-1 个是「写了一半」的孤儿；需要原子写（先写临时文件再 rename）。中风险。
- **#9 图片正则 `)` 吞字**：`_IMAGE_ALT_RE` 对图片 URL 里的字面 `)` 不转义。需要改写正则，且影响面在 URL 解析（中风险）。
- **#10 相对路径 CWD 漂移**：`_unique_cli_name` 拼接 `output_dir` 用 `os.path.join`，但下游 `Path(...)` 重新 resolve 时 CWD 已漂移。低-中风险。
- **#11 图片尺寸上限缺失**：LLM 图像描述前未做尺寸预检，大图 OOM。需要新增「大图降级」分支（中风险）。
- **#L5 / #L11 / #L15 / #L17 / #L19-L22**：零散低严重度项（空 `try` 块、`except BaseException`、裸 `except:`、重复 `add_warning` 等），逐项修复 ROI 低，列入后续。

> 本批次坚持「**降级、永不中止**」哲学：所有 11 项只做「兜底 / 防御 / 一致性」，不改写任何既有成功路径的行为。
